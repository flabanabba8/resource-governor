# Resource Governor

Watch a selected same-user Linux process against explicit resident-memory and average CPU budgets. The plugin records process and boot identities to avoid confusing a reused PID with the original, and rechecks process identity while collecting a sample. Monitoring reports exceedances without pausing, terminating or altering that process.
New watch records use owner-only POSIX permissions; existing records are not
retroactively changed. Watch records contain local process and boot identifiers.

An explicit read-only `resource_gpu_status` call reports NVIDIA device-wide memory usage via `nvidia-smi` without loading a model or reserving GPU memory. This point-in-time value can change immediately, does not attribute usage to individual processes, and does not enforce or reserve a budget. A separate explicit `resource_gpu_process` query checks NVIDIA compute-process entries for one same-user PID, with a process identity check. Graphics processes may be omitted, unavailable values are null, and an absent entry is not evidence of zero GPU usage. Systems without a working NVIDIA utility return an explicit error.

For a narrowly scoped managed job, explicitly select a trusted local video and run a separate CPU-only conversion into the plugin's private data directory. The plugin serializes its own conversion jobs and uses Linux `prlimit` to enforce an address-space limit, a CPU-time limit, a file-size cap and a shared wall-time limit. Encoding uses software FFmpeg with one thread and hardware acceleration disabled. Metadata verification runs separately with its own smaller CPU limit; neither stage inherits cloud credentials. Output metadata is stripped, and failures or timeouts remove partial output.

This is not a general job scheduler and does not enforce limits on other processes, child trees outside its owned process group, or GPU memory. Address-space limits measure virtual address space, not RSS. The output gets a metadata check but is not fully decoded or visually reviewed. Media parsing runs on the local machine; select files you trust. Access to media inside the active profile's plugin-data directory requires the explicit `allow_profile_media` option; unrelated private configuration remains blocked. Process monitoring and governed conversion require Linux `/proc`, `prlimit`, FFmpeg and ffprobe; on Windows those operations report the Linux requirement. Tests include a real small CPU conversion where the kernel limits were observed on both owned child processes; a short conversion of an Automatic Tutorial Creator export also passed a full decode. No production workload or Windows GPU telemetry test has been completed.
